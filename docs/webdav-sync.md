# WebDAV 同步（协议 v1 / 数据 v3）

## 使用

在桌面应用的「设置 → WebDAV 同步与冲突」填写 WebDAV 根地址、用户名、密码或应用专用密码、同步空间名称。两台设备使用同一地址和空间名称即可合并。使用 HTTPS；本机回环 HTTP 仅用于开发测试。

「测试连接」验证认证和目录读取；「立即同步」实际验证建目录、上传和下载。开启自动同步后，本地修改约 2.5 秒后上传，运行期间每分钟检查，恢复网络及窗口获得焦点时检查。存在未保存备忘录、正在编辑已有任务或打开业务编辑弹窗时延后同步，以免覆盖未提交编辑。失败采用最长 15 分钟的退避重试；可手动立即重试。

默认同步关闭。修改先写本地，不要求联网。界面显示待上传数量、未处理冲突、上次成功时间和错误。更换远端地址或空间会将本地全部版本与新空间合并，不会清空新空间。

同步空间固定使用 Asia/Shanghai。日期是日历日期，提醒时间按该时区解释；修改时间是 UTC 毫秒值。不同空间时区不兼容时停止同步，避免日期错位。

## 存储与迁移

桌面版使用 Tauri 应用数据目录中的 `todo-v3.sqlite3`。SQLite 开启 WAL、FULL 同步和立即事务。`document` 保存版本模型及本机状态，`revisions` 保存不可变版本索引，`outbox` 保存待上传版本，`migration_backup` 保留首次迁移的原始 localStorage 快照。任务、分类、每日完成记录、排序和备忘录由版本图投影；首版没有为这些投影重复建立实体表。

文档、版本和上传队列在同一事务内提交。数据库代数检查会阻止另一应用实例用旧快照覆盖新数据；出现提示时关闭重复实例并重新打开。写入失败会保留内存状态和待上传变更，并在界面提示；不要在保存失败时直接退出。

浏览器预览使用单独的 `floating-todo/v3-preview` localStorage 键，不连接 WebDAV；桌面版数据库失败不会退回浏览器存储。旧 `floating-todo/snapshot` 仅作迁移来源，桌面版不再用它作为当前数据源。

迁移保留任务 ID、分类 ID、提醒、设备设置和可确认的打卡状态。以旧 `lastActiveDate` 和分组计算计划日期；相同旧快照的初始版本通过 SHA-256 确定性去重。旧记录没有修改时间，初始版本时间为 0，冲突界面明确显示时间未知。历史连续打卡数作为基线保留，不伪造逐日记录。

原始 v1/v2 JSON 备份仍可导入。v3 备份包含完整版本历史和界面快照，不含 WebDAV 凭据、连接地址、上传队列和当前设备身份配置。版本来源设备 ID 作为历史元数据保留。导入前显示新增、修改、删除数量，确认后创建本机新版本；本机独有事项和设备设置保留。v3 备份不供旧版应用使用。

## 数据与合并

所有任务使用永久 UUID。普通任务保存 `scheduledDate`，每日任务另有以 `taskId/date` 为键的完成记录。`completed: false` 是明确的取消打卡状态。连续天数根据记录和迁移基线计算。

过期未完成任务在今天展示，原计划日期保留。已完成的过去任务退出主列表但保留历史；主动删除或清除才写删除版本。排序是独立实体，通常只更新被移动任务的位置，相同位置以稳定 ID 排序；间隔不足时重排该列表位置。

每个版本包含：

- `revisionId`、`entityType`、`entityId`、`deviceId`。
- `parentRevisionIds`：编辑所依据的版本；显式处理冲突时引用全部已展示的分支。
- `modifiedAt`、`logicalCounter`：混合逻辑时钟排序值。
- `deleted`：删除标记；`payload`：完整内容。

有继承关系的版本正常替代；并发分支按时间、逻辑计数、设备 ID、版本 ID 决定默认生效状态。整条任务合并，不做字段级自动合并。其他分支保留，包含删除状态；较新的编辑可以恢复被删除任务并提示。

冲突界面可保留当前版本、替换、编辑后保存或将任务另存为新任务。普通编辑保留未处理的其他分支，显式解决冲突才关闭分支。三台以上设备的并发修改全部保留。各端接收顺序不同、重复接收或时钟回拨不影响因果顺序；完全离线且时钟偏差时无法保证现实时间中的绝对先后，所以始终保留冲突分支。

项目和标签按规范化名称建立确定性 ID 映射，任务关联随映射投影；同名分类不同颜色也可在冲突界面恢复。删除分类解除关联，不默认删除任务。窗口状态、设备提醒开关和已提醒记录不参与同步；备忘录正文参与同步，展开状态不参与。

## 远端布局与传输

```
floating-todo/<space-id>/
  manifest.json
  changes/<device-id>/<batch-id>.json
```

`manifest.json` 保存协议版本、空间 ID 和时区。批次包含同样的协议/空间信息、批次 ID、来源设备 ID、版本数组及 SHA-256 校验。每批最多 100 个版本。请求和响应限制为 32 MiB；单条特别大的备忘录需要缩小后再同步。

Rust 客户端使用 GET、PUT、MKCOL、Depth:1 PROPFIND；不要求 WebDAV 扩展 REPORT。PUT 带 `If-None-Match: *`，随后 GET 校验内容。文件成功上传后不可变。上传批次先写入本地数据库，超时或重启后用相同批次重试；只有远端内容校验成功才移出队列。

同步流程为：确保空间 → 下载未知批次 → 应用并保存 → 上传本地队列 → 再下载一次。缺少祖先或有循环的版本不会投影为当前状态；等待依赖补齐。协议不兼容、校验失败、同一版本 ID 内容变化时停止同步并保留本地队列。

目录响应中的外域、根目录外路径和非协议文件被忽略。网络不跟随重定向，需填写最终 WebDAV 地址。密码通过 macOS Keychain 或 Windows Credential Manager 保存；JSON 文件未做端到端加密，服务端可以读取。

首版不自动删除历史版本、删除标记或远端变更文件。检查点、垃圾回收、RFC 6578 增量目录、端到端加密以及文件夹/S3 后端留作后续扩展。不要通过手工删除远端批次来删除任务。

## 验证

- `npm test`：迁移、并发、删除恢复、乱序/重复、时钟回拨、跨天、每日完成、排序、分类别名，以及模拟 WebDAV 两设备同步、丢失响应重试和本地写入失败。
- `npm run test:ui`：现有界面回归及原生存储桥接、WebDAV 设置、备份凭据隔离、冲突恢复/编辑。可设置 `PLAYWRIGHT_CHANNEL=chrome` 使用已安装 Chrome。
- `cargo test --manifest-path src-tauri/Cargo.toml --lib --locked`：SQLite 原子回滚/代数、WebDAV URL/路径验证和本地 HTTP 条件写入。

浏览器和模拟服务器验证不能替代具体服务商兼容测试。首次使用新的 WebDAV 服务，先测试连接，再在两台设备上分别新增、离线修改同一任务并联网确认冲突恢复。
